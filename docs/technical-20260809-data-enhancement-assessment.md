# 数据增强技术评估

评估日期：2026-08-09

范围：只读检查现有实现，给出导入表头兼容、格式扩展、词元下钻广告活动、撤销恢复的最小正确实现路径。本评估不修改源码。

## 结论

当前程序的数据层已经保存了`cost`、`sales`和`campaign`，筛选、排行、搜索也共用同一个DuckDB数据集。增加成本、销售额表头兼容，或在下钻结果展示广告活动，不需要迁移历史数据库结构。

当前导入仅接受`.xlsx`，并且只接受完全等于`搜索词、展示量、点击量、购买量`的四个必需表头；成本仅识别`总成本`，销售额仅识别`销售额`。词元表双击已经会调用搜索并显示完整搜索词，但没有返回或展示广告活动名。

新数据成功导入后会通过`os.replace`覆盖`current.duckdb`，没有批次恢复。查询、排序、筛选属于内存界面状态，目前也没有通用撤销、重做栈。

## 1. 导入表头与字段映射

### 现状

`src/token_analyzer/core.py:14-22`定义了固定表头：

| 业务字段 | 当前源表头 | DuckDB列 | 是否必需 |
| --- | --- | --- | --- |
| 搜索词 | `搜索词` | `search_term` | 是 |
| 展示量 | `展示量` | `impressions` | 是 |
| 点击量 | `点击量` | `clicks` | 是 |
| 购买量 | `购买量` | `orders` | 是 |
| 预算货币 | `预算货币` | `currency` | 否 |
| 日期范围 | `日期范围` | `date_range` | 否 |
| 广告组合名称 | `广告组合名称` | `portfolio` | 否 |
| 广告活动名称 | `广告活动名称` | `campaign` | 否 |
| 广告组名称 | `广告组名称` | `ad_group` | 否 |
| 总成本 | `总成本` | `cost` | 否 |
| 销售额 | `销售额` | `sales` | 否 |

`_read_source()`在读取数据前用精确表头检查必需字段，再通过`usecols`只读取上述字段，见`core.py:146-206`。数值无法转换时被填为`0`，空搜索词会被跳过。导入后`import_workbook()`把规范化DataFrame写入`search_records`表，并以`record_id`和拆词表`token_records`建立查询索引，见`core.py:209-261`。

### 建议的映射规则

在读取数据前增加独立的`resolve_headers(raw_columns)`：先对表头做NFKC规范化、去首尾空白、大小写折叠，再以别名字典映射为规范业务字段。读取时仍使用原始列名，读取后一次性重命名为规范字段。这样不会把源文件的实际列名传进业务查询层。

同一规范字段命中多个源列时，不能静默挑一列。应显示冲突列并拒绝导入，例如同一文件同时有`7天总销售额`和`14天总销售额`。不同归因窗口的金额口径不能合并。

建议别名如下。英文别名应按大小写不敏感处理，中文括号、全半角和首尾空格按规范化结果处理。

| 规范字段 | 建议识别的常见表头 |
| --- | --- |
| 搜索词 | `搜索词`、`搜索词条`、`客户搜索词`、`Search Term`、`Customer Search Term` |
| 展示量 | `展示量`、`曝光量`、`Impressions` |
| 点击量 | `点击量`、`点击`、`Clicks` |
| 购买量 | `购买量`、`订单量`、`订单数`、`Purchases`、`Orders`、`7 Day Total Orders (#)`、`14 Day Total Orders (#)` |
| 成本 | `总成本`、`成本`、`花费`、`支出`、`广告花费`、`广告费用`、`Spend`、`Cost`、`Total Cost`、`Ad Spend` |
| 销售额，无归因窗口 | `销售额`、`总销售额`、`广告销售额`、`归因销售额`、`成交金额`、`销售金额`、`Sales`、`Total Sales`、`Attributed Sales` |
| 销售额，归因窗口 | `7天总销售额`、`14天总销售额`、`30天总销售额`、`7 Day Total Sales`、`14 Day Total Sales`、`30 Day Total Sales` |
| 广告活动 | `广告活动名称`、`广告活动`、`Campaign Name`、`Campaign` |
| 广告组合 | `广告组合名称`、`广告组合`、`Portfolio Name`、`Portfolio` |
| 广告组 | `广告组名称`、`广告组`、`Ad Group Name`、`Ad Group` |
| 币种 | `预算货币`、`币种`、`Currency` |
| 日期 | `日期范围`、`日期`、`Date Range`、`Date` |

不应把`每次点击成本、CPC、ACOS、ROAS、新客销售额`自动映射到成本或销售额：前两类是派生指标，新客销售额是不同业务口径。若要支持归因窗口销售额，导入预览应显示命中的原表头和归因窗口；多个窗口同时存在时要求用户只选一个，或明确产品规则后按固定窗口优先级选择。

两个实现细节会影响后续改动：

1. `cost`和`sales`目前只被保存，没有进入KPI、排行、搜索行或AI评分，因此表头兼容本身不会改变现有展示结果

## 3. `.csv`、`.xlsm`、`.txt`导入的最小正确路径

### 数据层

1. 将`_read_source()`改为按扩展名路由，而不是限制`.xlsx`
2. `.xlsx`和`.xlsm`继续使用`pandas.read_excel(..., sheet_name=0, engine="calamine")`。`.xlsm`只读取单元格值，不执行VBA宏
3. `.csv`使用`pandas.read_csv`。`.txt`按分隔文本处理，先读取少量原始字节，处理UTF-8 BOM，再在`utf-8-sig、utf-16、gb18030`中确定可解码编码，并从逗号、制表符、分号、竖线中识别分隔符
4. 先只读取表头或小样本做表头映射和必需字段校验，确认后仅读取需要的源列，重命名为规范字段，再复用现有清洗与DuckDB写入逻辑
5. 编码、分隔符无法判断，或必需字段缺失、别名冲突时中止导入，旧库保持不变。不要把单列文本误当成成功导入

保持`import_workbook()`的暂存库加`os.replace`流程不变，导入失败仍保留旧`current.duckdb`。`ImportThread`也可复用。

### 界面与测试

1. `MainWindow.choose_file()`，`app.py:958-981`的文件选择器扩展为`.xlsx、.xlsm、.csv、.txt`，空状态、来源说明、失败提示同步改为通用的导入文件文案
2. 为每种格式各建一个最小夹具，至少覆盖UTF-8 BOM CSV、GB18030 CSV、Tab TXT、XLSM首工作表、别名映射、冲突销售额列、失败后旧数据库未被替换
3. `.txt`仅承诺分隔文本，不承诺任意自由文本。无标题、固定宽度文本和多表混合文件应明确报错

这是最小正确范围。若要在导入时让用户手动选择字段或归因窗口，需要额外增加导入预览对话框，不能放在后台导入线程里临时弹窗。

## 4. 词元双击下钻并展示广告活动

### 已有能力

当前双击词元首列已经完成下钻：`QTableWidget.cellDoubleClicked`连接到`search_selected_token()`，它设置搜索框并调用`run_query()`。`query_phrase()`随后返回包含该词元、且保持连续顺序的完整搜索词聚合列表。筛选会透传，因此先按广告活动筛选再双击的范围是正确的。

目前的限制是：

1. 下钻入口依赖`self.table_title.text() == "词元排行"`，属于显示文本耦合，建议改为`self.view_mode == "ranking"`
2. `query_phrase()`只按`search_term`聚合，行字典只有7项指标，没有广告活动名
3. 搜索表固定为7列，`render_result()`也只渲染这7列

### 最小改动方案

不改数据库表。`search_records.campaign`已经存在，查询时聚合即可。

1. 在`QueryResult.rows`的搜索结果行增加`campaigns`字段，值为非空、去重、排序后的广告活动名列表，或先在SQL中返回列表再在Python中格式化
2. 修改`query_phrase()`的`matched_summary`，在按`search_term`汇总指标的同一层增加活动聚合。例如DuckDB侧可返回`list_sort(list_distinct(list(campaign))) FILTER (WHERE campaign <> '')`，避免用拼接字符串承载数据
3. 在`run_query()`把搜索结果表头从7列扩展为8列，在`render_result()`按`view_mode == "search"`渲染广告活动列；排行页仍是7列
4. 第一列保留完整搜索词，活动列显示`、`连接后的名称并设悬停全文。活动数量很大时显示前若干项加`等N个活动`，完整列表放Tooltip，避免表格不可读
5. `search_selected_token()`改为检查`view_mode`，并保留当前排序和筛选条件

若需求是看到某个完整搜索词在每个广告活动中的各自指标，不能只加活动名称列表，需要增加二级明细：`GROUP BY search_term, campaign`，或点击搜索词后打开明细表。前述最小方案只回答涉及哪些活动，以及该完整搜索词的全活动汇总指标。

需要补的验证：同一完整搜索词在多个活动中出现时，指标汇总不重复计数、活动列表去重且排序稳定；空活动名不显示；筛选广告活动后列表只保留筛选范围内活动；双击排行词元后仍按当前排序显示。

## 5. 撤销与恢复可以覆盖的动作

### 当前可恢复能力

| 动作 | 当前行为 | 恢复情况 |
| --- | --- | --- |
| 导入失败 | 暂存库失败不会替换旧库 | 自动保留旧数据 |
| 成功导入新文件 | 原子替换`current.duckdb` | 无恢复入口，界面明确提示没有批次恢复 |
| 清空搜索 | 回到词元排行 | 用户可重新输入原搜索词，但无历史 |
| 重置筛选 | 清空全部筛选，保留搜索与排序 | 无法恢复上一个筛选组合 |
| 排序、加载更多、列宽 | 即时改变界面 | 无撤销、重做 |
| AI推荐 | 只读当前数据，成功后清空本次补充要求 | 不应把重新调用模型作为重做 |
| 模型配置、自定义权重 | 写入本机设置 | 对话框取消可放弃未保存内容，已保存内容无历史 |

### 建议分两层实现

**界面状态撤销、重做**适合以下无副作用动作：

- 输入或清空辅助搜索，包括词元双击触发的下钻
- 应用、重置筛选
- 切换排序
- 加载更多、加载全部
- 侧栏展开状态、表格列宽仅在产品确实希望撤销时纳入

每个快照应包含`view_mode、active_query、active_filters、sort_by、ranking_limit、search_limit`。恢复快照后只重新查询，不重新导入或调用模型。把连续输入搜索框合并为一次动作，避免每个按键占一个历史条目。

**持久数据恢复**只适合成功导入。应与界面撤销栈分开，保存最近一个或多个完整数据库快照和批次清单，批次信息包含来源文件路径、导入时间、有效行数、文件指纹、备份文件路径。恢复旧批次前再次确认，恢复时也用暂存文件和原子替换。这个动作不应依赖内存中的`QUndoStack`，因为重启后仍要可恢复。

不建议纳入通用撤销的动作：

- 已发出的AI请求、连接测试等可能计费的网络行为，只记录状态，不能用重做再次发起请求
- API密钥、模型设置的历史版本，除非另行设计加密的有限版本存储和删除策略
- 导入过程中的半完成状态，任务运行时只允许取消或等待完成，不能撤销到一个未完成数据库

建议优先级：先做查询、筛选、排序、下钻的一步撤销和重做，再做最近一次导入批次恢复。后者是数据丢失风险控制，价值高于把列宽加入撤销。

## 实施顺序与回归范围

1. 先完成表头解析和四种格式读取，保留现有规范化、写库和原子替换链路
2. 添加下钻广告活动字段与8列表格，再覆盖词元、搜索、筛选组合的回归测试
3. 最后增加界面状态快照和独立的批次备份、恢复机制

核心回归点：现有`.xlsx`精确中文表头仍可导入；失败导入不覆盖旧库；6项筛选继续同时影响KPI、Top10、排行、搜索、AI候选；词元双击仍只匹配连续、同顺序的完整搜索词；成本和销售额新别名写入`search_records`后不改变现有点击率、转化率口径。
